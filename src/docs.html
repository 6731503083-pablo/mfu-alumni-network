Mentoring API

The PRD's nine endpoints. Students find alumni and ask for mentoring, and alumni decide what they share.

Sign in for testing

Every Mentoring API call needs a token in the Authorization: Bearer header, except the Events & Clubs webhook. Until the Identity service publishes its token contract, tokens are HS256 JWTs signed with JWT_SECRET.

Token claims

ClaimWhat it holds
subRequiredThe user's ID. user_id also works.
roleRequiredstudent, alumni or admin.
expRequiredExpiry time. A token without one is rejected.

Errors on any call that needs a token

StatusMeaning
401UNAUTHENTICATED: the token is missing, invalid or expired.
403FORBIDDEN: your role can't call this endpoint.
503AUTH_NOT_CONFIGURED: the server has no JWT_SECRET.

Errors look like this, with fields on a 400:

{ "error": "Some fields are invalid", "code": "VALIDATION_ERROR", "fields": { "message": "..." } }

Try the whole flow

  1. Add the JWT secret on this page.
  2. Create a profile as Alumni 1.
  3. Send a request as Student 1.
  4. Accept it as Alumni 1.
  5. View the profile as Student 1 to see the shared contact details.
  6. End the connection.

IDs carry over from one step to the next.

When running locally, it's JWT_SECRET in .dev.vars. It signs test tokens in this browser, and it isn't sent or saved.

Choose "Pasted token" under "Send as" to use it.

No secret yet, so signed-in calls return 401.

Sign in with the demo passcode

POST /auth/demo-login

How the web app at /app signs people in until the Identity service publishes its login. It returns a two-hour token for a demo account, so the browser never needs JWT_SECRET. It only signs in IDs that start with demo-, so it can't be used to act as a real user.

Body

FieldWhat to send
passcodeRequiredThe demo passcode, set as the DEMO_PASSCODE secret.
roleRequiredstudent, alumni or admin.
user_idRequiredAn ID that starts with demo-, such as demo-student-su-myat.

Responses

StatusMeaning
200Signed in.{ token, expires_at, user: { id, role } }
400A field is invalid, or the ID doesn't start with demo-.{ error, code, fields }
401INVALID_PASSCODE: the passcode is wrong.
503DEMO_LOGIN_NOT_CONFIGURED: the server has no DEMO_PASSCODE.

View a profile

GET /alumni/{id} API-02

For students, alumni and admins. What comes back depends on who's asking. Admins see public fields only.

What each person sees

Who's askingWhat they see
Anyone signed inName, graduation year, faculty, job title, company, location, bio, interests and mentoring availability.
A student connected to this alumniAll of that, plus contact with only the details the alumni shares right now.
The alumni who owns itEverything, including every contact detail and consent setting.

When an alumni stops sharing a detail, it disappears on the next request, even inside an active connection.

Responses

StatusMeaning
200The profile, as described above.
404There's no profile with this ID, or it has been deactivated.

Accept, reject or cancel

PATCH /mentoring-requests/{id} API-06

Answers or withdraws a pending request. A request that's already closed can't change.

Body

statusWho can set it
acceptedThe alumni who received the request.
rejectedThe alumni who received the request.
cancelledThe student who sent the request.

Accepting either does all of this or none of it: checks capacity, marks the request accepted, creates the connection, logs each contact detail the student can now see, and queues an alumni.connection_created event.

Queued events aren't sent yet. The delivery job isn't built, so they wait in webhook_outbox.

Responses

StatusMeaning
200The updated request. connection is null unless it was accepted, and accepting adds revealed_fields.{ ...request, connection, revealed_fields }
400The status isn't one of the three above.
403NOT_OWNER: only the people in the table above can do this.
404There's no request with this ID.
409INVALID_STATE: the request isn't pending anymore.
409CAPACITY_FULL: the alumni has no mentee slots left.
409ALUMNI_INACTIVE: this profile has been deactivated.

The response appears here.

End a connection

DELETE /connections/{id} API-07

Either side can end it. The record stays, the student stops seeing contact details, and the alumni gets a mentee slot back.

StatusMeaning

403NOT_OWNER: you aren't part of this connection.
404There's no connection with this ID.
409INVALID_STATE: this connection has already ended.

Deactivate a profile

PATCH /admin/alumni/{id}/deactivate API-08

For admins. Removes the profile from search and profile views, and blocks new requests to it. It returns status fields only, with no contact details. Repeating it is safe.

There's no undo. No route reactivates a profile.

Responses

StatusMeaning
200The profile is deactivated.{ id, is_active: false }
404There's no profile with this ID.

The response appears here.

Receive an alumni event

POST /webhooks/events-clubs API-09

Events & Clubs posts alumni events here. The signature replaces a token. A bad event is logged and skipped, and a retried event is stored once.

This is a draft contract. Events & Clubs hasn't published its schema, so this shape follows the Week 06 lab. Stored events aren't shown to students yet.

Request

FieldWhat to send
X-Webhook-SignatureHeader, requiredHex HMAC-SHA256 of the raw body, keyed with EVENTS_CLUBS_WEBHOOK_SECRET.
event_idRequiredUnique event ID. A repeated ID counts as a retry.
event_typeRequiredMust be alumni.event.
occurred_atRequiredISO 8601 time.
data.titleRequired1 to 200 characters.
data.starts_atRequiredISO 8601 time.
data.faculty_id
data.interests
data.urlOptional		Who the event is for, and an http or https link to it.

Responses

StatusMeaning
200Event stored.{ received: true }
200This event ID is already stored, so nothing changed.{ received: true, duplicate: true }
400The signature is valid but the event isn't. It's logged and skipped.{ error, code, fields }
401INVALID_SIGNATURE: the signature is missing or wrong.
503WEBHOOK_NOT_CONFIGURED: the server has no secret for this webhook.

Signs the body in this browser. It isn't sent or saved. Leave it empty to see the 401.

The response appears here.

Check Team 17's status

GET /api/partner/status

This service calls Team 17's status endpoint and passes back the answer. It stops waiting after 5 seconds, so a dead partner can't hang the request.

Responses

StatusMeaning
200Team 17 answered. The body is their JSON, unchanged.
502Team 17 answered with an error.{ error, status }
504Team 17 didn't answer within 5 seconds, or its answer wasn't JSON.{ error, detail }

The first call after a quiet spell can time out. Send it again before assuming Team 17 is down.

The response appears here.

Receive a Team 17 webhook

POST /api/webhooks/partner

Team 17 posts events here. This service checks the signature, then stores each event once, however many times it's delivered.

Request

FieldWhat to send
X-Webhook-SignatureHeader, requiredHex HMAC-SHA256 of the raw body, keyed with the shared WEBHOOK_SECRET.
idBody, requiredUnique event ID. A repeated ID counts as a retry.
typeBody, requiredEvent name, such as internship.status_changed.
dataBody, optionalEvent details. Stored with the rest of the body.

Responses

StatusMeaning
200Event stored.{ received: true }
200This event ID is already stored, so nothing changed.{ received: true, duplicate: true }
401The signature is missing or wrong.{ error: "invalid signature" }
500The signature is valid, but the body isn't JSON.{ error, code }

Always send id and type. An event missing either one isn't stored, but it still gets the duplicate: true reply.

Signs the body in this browser. It isn't sent or saved. Leave it empty to see the 401.

The response appears here.

Send Team 17 a test webhook

POST /api/webhooks/send-test

Takes no body. This service posts a partner.updated event to Team 17's receiver, with their shared secret in X-Webhook-Secret. That's a plain secret rather than a signature, because each receiver sets its own rules.

What Team 17 receives

{
  "event_id": "alumni-team17-handshake-<timestamp>",
  "event_type": "partner.updated",
  "occurred_at": "<ISO 8601 time>",
  "source": "pod5-alumni-network",
  "data": { "resource_id": "alumni-demo-001", "status": "updated" }
}

Responses

StatusMeaning
200Team 17 answered. Check partnerStatus, because this stays 200 even if they rejected the event.{ sent: true, partnerStatus, partnerBody }
504Team 17 didn't answer within 5 seconds.{ error, detail }

This reaches a live system. Every send posts a real event to Team 17, even from a local server.

The response appears here.

Try an idempotent create

POST /api/connections

A lab demo, separate from real connections, which only come from accepting a request. Retrying with the same Idempotency-Key returns the first result, so a retry can't create a second one.

Request

FieldWhat to send
Idempotency-KeyHeader, requiredAny unique string.
JSON objectBody, requiredSuch as { "studentId": 1, "alumniId": 1 }. Fields are copied into the result without validation.

Responses

StatusMeaning
201Created.{ id, ...your fields, createdAt }
200This key was already used. You get the first result, and this request's body is ignored.
400No key was sent.{ error: "Idempotency-Key header required" }
500The body isn't valid JSON.{ error, code }

Send twice with the same key to see the first result come back.
